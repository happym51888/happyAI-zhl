## 什么是 Agent

**Agent** 是让 LLM 围绕目标反复规划、调用工具、观察结果并继续决策，直到完成任务或触发停止条件的应用系统。

最基本的循环是：

```text
理解目标 → 规划下一步 → 调用工具 → 观察结果 → 更新状态 → 继续或结束
```

## 工具

**工具（Tool）**是 Agent 被允许调用的外部能力，例如搜索、数据库查询、代码执行、文件读取或业务 API。

每个工具都应该具备：

- 明确、准确的功能描述。
- 可验证的参数 Schema。
- 最小权限。
- 超时、错误和重试策略。
- 必要时的人工审批。

## 规划

**规划（Planning）**是把目标拆成步骤，并根据执行结果动态调整后续行动。

不是所有任务都应该由 LLM 自由规划；固定步骤更适合普通程序或工作流，只有不确定的决策点才需要模型判断。

## Observation

**Observation** 是工具执行后返回给 Agent 的结果，模型会利用它判断任务是否完成以及下一步做什么。

工具结果属于外部输入，不能因为它来自“工具”就自动视为可信指令。

## 记忆与状态

**记忆（Memory）**保存对话、用户偏好或历史经验，供后续步骤或其他会话继续使用。

**状态（State）**记录当前运行的消息、步骤、工具结果、错误和执行位置，是一次任务的实时快照。

简单来说：状态主要回答“这次任务现在进行到哪里”，记忆主要回答“过去有什么值得以后继续使用”。

## Human-in-the-loop

**Human-in-the-loop** 会在高风险、模糊或重要步骤暂停 Agent，让人类审核、修改或批准。

发送消息、修改生产数据、执行命令、产生费用或删除内容等动作，通常不应完全交给无人监督的 Agent。

## 什么时候不需要 Agent

- 一次 LLM 调用已经可以完成。
- 步骤完全固定，可以写成普通工作流。
- 错误代价很高，但无法有效验证结果。
- 没有明确的权限和停止条件。

Agent 会增加延迟、成本和不确定性，因此应从能够完成任务的最简单方案开始。
